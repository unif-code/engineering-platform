# 前端原型高保真对齐设计

## 目标

以最新研发协作平台原型为唯一界面事实源，在不回退既有路由、权限、契约和可访问性能力的前提下，将桌面端页面重构到至少 95% 的视觉与交互保真度。

本设计取代此前计划中与视觉呈现冲突的内容，但不取代已确认的架构、服务契约、Route Registry、Session、权限或 V0.2 管理能力设计。

## 设计原则

### 原型决定呈现

- 页面结构、区块顺序、控件数量、文字、间距、密度、颜色、状态和操作入口均以原型为准。
- 原型没有的搜索、筛选、摘要、指标卡或说明文案不得自行显示。
- 已有契约能力若原型没有独立入口，应放入原型已有的弹窗、抽屉或操作区域，不新增抢占主界面的区块。
- 原型已有的静态交互必须保留可操作反馈，不把可点击元素退化为纯文本。

### 官方组件负责能力，Token 负责外观

- 优先使用 Ant Design 6、Pro Components 3 和 Ant Design Charts 的公开组件。
- 使用公开 props、全局 Token、组件 Token、`styles` 和 `classNames` 对齐原型；不依赖内部 `.ant-*` DOM 或全局覆盖。
- ProTable 仍负责异步 `request`、排序、分页和稳定 `rowKey`，但关闭原型没有的内置工具栏、搜索表单和密度入口。
- 原型中的紧凑表格统一使用 `size="small"`。筛选器、分页和工具栏控件同样采用小尺寸密度。
- 原型没有下拉筛选时，不因 ProTable 或 Select 方便而新增筛选器。

### 中文主文案与技术标识并存

- 页面主文案、操作、状态和帮助信息使用中文。
- 领域术语、API 字段名和不可翻译标识作为次级英文文案展示。
- 推荐格式包括 `策略标识（Policy Key）`、`授权主体（Principal）`、`能力（Capability）`、`范围（Scope）`、`关联标识（Correlation ID）`。
- 表头可使用中文主标题与下方小号英文/API 字段名，但不得让整块界面以英文为主。
- Route Key、Capability Key、模型名、部署名、错误码和业务数据保持原值。

## 统一视觉系统

### 色彩

浅色原型的关键色固定为：

- 主色与链接：`#EB6E00`
- 主色悬停：`#FF8F2E`
- 深色主文本：`#191919`
- 页面背景：`#F5F5F5`
- 容器背景：`#FFFFFF`
- 表头与弱背景：`#FAFAFA`
- 常规边框：`#F0F0F0`
- 输入边框：`#D9D9D9`
- 危险色：`#CF1322`
- 成功色：`#389E0D`
- 警告色：`#D48806`

主题配置同时设置全局语义 Token：`colorPrimary`、`colorLink`、`colorLinkHover`、`colorInfo`、背景、文本、边框、圆角和控件高度。深色模式使用原型对应颜色并通过 `darkAlgorithm` 派生，不在页面里写浅色专属覆盖。

组件 Token 负责消除默认蓝色和默认大密度：

- Table：表头背景/文字、行悬停、选中、排序、边框、small 单元格字体和内边距。
- Button：primary、link、text、default 的正常/悬停/激活颜色和 small 字号、间距。
- Select/Input：焦点边框、outline、选中选项、悬停边框和 small 高度。
- Pagination：选中页、悬停页和 small 尺寸。
- Menu：选中项、悬停项、分组标题和折叠状态。

表格操作区的普通链接按钮使用原型橙色；危险操作保持危险色，禁用操作保持中性色。

### 密度与布局

- 应用壳头部高 52px，展开菜单宽 208px，折叠菜单宽 64px。
- 页面内容采用原型的 20px × 24px 内边距。
- 卡片通常使用 8px 圆角、1px 次级边框和轻量阴影；原型无阴影时不得额外添加。
- 表格表头、行高、字体和操作间距按 small 密度配置，不使用 antd 6 Table 默认 `large`。
- Select 默认 `medium`，因此原型工具栏中的 Select 必须显式设置 `size="small"`。
- 布局优先使用 Grid/Flex 表达原型关系，不为单个截图堆叠绝对定位和媒体查询。
- 表格宽度不足时只允许表格容器内部横向滚动，页面不得产生全局横向溢出。

## 图表方案

- 新增并统一使用 `@ant-design/charts` 实现趋势、分布、柱状和堆叠图。
- 移除手写图形组件承担的图表绘制职责，包括 `MiniBarChart` 和 `DistributionBar`。
- 指标卡不是图表，可继续使用共享 MetricCard，但必须按原型对齐边框、字号和间距。
- 图表颜色、轴、标签、圆角、间距、tooltip 和动画按原型配置。
- `prefers-reduced-motion` 时关闭或缩短图表动画，保留可访问名称和数据摘要。

### 架构保留页面

组织管理、Grant 管理和 Policy 发布没有独立原型屏幕，但属于必须保留的架构能力：

- 三项均作为独立菜单项，不合并进管理概览或其他页面。
- 菜单和菜单管理目录名称分别显示为 `组织管理（新增）`、`Grant 管理（新增）`、`Policy 发布（新增）`。
- 页面内部标题仍使用正常业务名称，不附加“新增”。
- 视觉样式复用最接近的原型管理页：组织管理采用工作区管理的紧凑主从布局；Grant 管理采用用户/菜单管理的紧凑表格与弹窗；Policy 发布采用模型管理的 Tab 与抽屉/弹窗结构。
- 三页保留现有 API、reason、If-Match、错误处理和竞态保护，不因视觉重构退回静态壳。

### 兼容路由

- `/admin` 管理概览保留为兼容直达路由。
- 管理概览不进入侧栏，也不进入菜单管理目录。
- 侧栏管理端顺序从工作区管理开始，随后为组织管理（新增）及其他独立管理能力。

## 页面实现边界

- `src/pages/` 继续只承担当前仓库既有路由装配；本次不借视觉重构扩大领域架构迁移。
- 已存在的服务层、React Query、ProTable `request`、错误归一和 Route Registry 不重写。
- 可复用的原型视觉结构提取为共享组件或共享 Token；只有两个及以上页面实际复用时才提升。
- 创建、编辑和内容较长的操作使用 Modal 或 Drawer，避免把编辑器常驻在主页面造成拥挤。
- 弹层关闭后恢复焦点，键盘操作和 accessible name 保持可验证。
- 不修改 `src/.umi/`、`dist/`、`coverage/`、`.turbopack/` 等生成目录。

## 测试与验收

### TDD

每个页面按以下顺序执行：

1. 保留既有行为测试。
2. 新增该页面的原型视觉契约测试并取得有效 RED。
3. 最小改造到 GREEN。
4. 运行该页面 focused tests、Biome、TypeScript 和 antd lint。
5. 完成同批页面浏览器对照后再进入下一批。

视觉契约测试至少覆盖：

- 原型控件存在且顺序正确。
- 原型没有的筛选、摘要、页头和额外操作不存在。
- Table/ProTable、Select、Pagination 和工具栏使用 small 密度。
- 中文主文案与英文/API 次级标识正确。
- 额外架构菜单具有“（新增）”，普通原型菜单没有该标识。
- 菜单、路由和菜单管理目录名称一致。

### 高保真验收

95% 不是用主观“看起来差不多”判断，验收标准为：

- 页面区块、控件、文案和交互入口 100% 对齐原型清单。
- 不存在未经确认的额外可见内容。
- 关键高度、间距和圆角与原型差异不超过 4px。
- 栅格列宽比例与原型差异不超过 5%。
- 主色、背景、边框、状态色使用原型固定值或对应深色值。
- 每个原型屏幕完成浏览器逐页对照，记录 PASS/FAIL/CANNOT VERIFY。
- 原型已有的浅色与深色状态都能正确呈现。

### 完整门禁

所有页面完成后运行：

- `pnpm lint`
- `pnpm test`
- `pnpm test:coverage`
- `pnpm doctor`
- `pnpm antd:check`
- `pnpm build`

不得通过增加全局 timeout、重试、sleep、扩大 ignore/exclude 或隐藏 warning 伪造通过。

## 非目标

- 不重新设计原型。
- 不新建与已有页面平行的替代页。
- 不借机更改后端契约、权限模型或 OpenAPI Artifact。
- 不把原型静态数据误写为真实持久化能力。
- 不为了追求像素相似而复制 antd 已提供的基础控件。
