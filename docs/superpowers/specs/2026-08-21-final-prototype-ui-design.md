## 1. 最终裁决

本轮不是在现有页面上叠加原型区块，而是以 2026-08-21 最终原型作为页面结构、信息层级、文案位置和交互入口的唯一视觉事实源。现有页面只提供可复用的真实数据链路；旧布局、重复入口、演示交互和静态业务记录在对应页面完成迁移后删除。

“最终原型”只表示本轮设计事实源已经锁定，不表示当前代码已经成为已发布最终版。当前产物是开发候选版本；只有完整 CI、真实联调和发布验收通过后，才能宣称最终版。

事实源按以下顺序分工：

1. 最终原型决定屏幕、布局、信息密度和操作入口。
2. V0.1/V0.2 已发布 OpenAPI 与现有 Feature service 决定可用数据和业务动作。
3. 后端 `navigation` 决定当前用户可见菜单；前端不得以角色名、工号或静态菜单替代授权。
4. 没有真实接口的数据区域展示加载、空、错误或“暂未接入”状态，不伪造业务记录。

## 2. 明确覆盖旧方案的规则

- 不保留旧页面并新增一个“原型版”页面；每项能力只有一个最终路由和一个最终页面。
- 当前处于开发阶段，只维护最新目标的一条实现路径，不保留任何历史兼容路由、别名、旧 DTO 适配器、deprecated 包装、双写或 fallback。旧入口和旧模型直接删除；需要改变结构时以最新架构重写。
- 不把原型功能以额外 Card、Tab、Drawer 或按钮堆到旧页面上；页面 DOM 以最终原型重新组织。
- 不保留生产环境的 `*FIXTURE*`、`useStaticPrototypeAction`、演示角色切换、异常态演示、重置演示数据或“静态原型操作”提示。
- 不新增 Umi Mock、MSW、运行时假接口或页面内静态 request adapter。
- 测试可以动态构造 DTO，但测试数据不得进入生产 bundle。
- 现有真实 API 不回退为假数据；页面重构只移动其呈现位置，不手改 generated client，也不自行设计新接口。
- 原型中出现但后端尚未提供的动作保留正确视觉位置并禁用，Tooltip 统一说明“当前版本暂未接入”，不得点击后伪造成功。

## 4. 视觉系统

- 使用原型 D 形 Brand Mark 和产品名“研发协作平台”。
- 主色 `#EB6E00`；深色侧栏 `#191919`；Header 高度 `52px`；侧栏展开 `208px`、折叠 `56px`；页面内边距 `20px 24px`。
- 优先级固定为 ProComponents → Ant Design → `antd-style` token/语义样式；只有官方组件无法表达的布局才写页面私有样式。
- ProLayout、Menu、Table、Button、Input、Select、Drawer、Modal、Tabs 和 Empty 使用公开 API 与 token，不查询或覆盖内部 `.ant-*` DOM。
- 1280px 以上桌面优先；表格显式提供 `scroll.x`，内容区拥有唯一页面滚动条。
- 明暗主题保留，但侧栏保持最终原型的深色品牌外观；内容区由 Ant Design algorithm 和 token 切换。

## 5. 数据与状态

每个数据容器必须具备四态：

1. loading：使用 ProTable loading、Skeleton 或 Spin。
2. success：只渲染服务端 DTO 转换后的数据。
3. empty：使用 Ant Design Empty，文案说明当前没有真实数据。
4. error：展示归一化 Problem Details；保留 `requestId`，不得用假数据回退。

无接口页面直接进入 empty/disabled 状态。空态仍保留原型的标题、筛选、Tabs、列头和空间关系，使界面可验收，但不显示任何虚构姓名、任务、仓库、模型、技能、角色、统计值或趋势。

## 6. 导航与去重

- `ROUTE_REGISTRY` 是前端 path、图标和分组的唯一注册表；Umi routes 与其保持一一对应。
- 菜单内容只投影后端 navigation 返回的已知 routeKey；未知 routeKey fail closed。
- 管理概览不额外复制各管理页的操作；只提供状态与导航入口。
- 任务创建只存在于任务列表/工作台指向的同一个 Modal；任务归档是任务列表视图，不是独立能力页面。
- Bootstrap 复用 LoginShell；403 复用一个 AccessDenied 页面。
- 原型设计工具中的角色切换器、异常态面板、假登录、重置数据和 demo localStorage 全部排除。

## 7. 测试与门禁

- 每个小改动只运行受影响页面测试、Biome changed files、`pnpm tsc` 和 scoped antd lint；不在本地每次运行全量 coverage。
- 每个页面测试必须从真实页面边界验证标题、主要区域、空/错态和真实动作 wiring；不得只 import 常量或只追求执行行数。
- 结构门禁禁止生产源码出现 `Fixture`/`FIXTURE` 标识、`useStaticPrototypeAction`、`prototype: true`、运行时 mock 目录或“静态原型操作”文案。
- 完成全部页面后，CI 运行完整 `pnpm verify`；本机只在最终收口且资源允许时运行等价完整门禁。
- 浏览器视觉验收必须使用用户已安装插件的外部 Chrome；插件不可用时记录 CANNOT VERIFY，不使用应用内浏览器替代。

## 8. 验收标准

1. 19 个最终屏幕均有且仅有一个产品实现；旧页面、旧路由、重复入口和兼容层全部删除。
2. 视觉结构与最终原型一致；原型中没有的旧卡片、筛选、动作和文案不再出现。
3. V0.1/V0.2 已完成接口仍真实工作，且位于原型对应区域。
4. 没有接口的区域不展示假记录、假指标、假图表或假成功反馈。
5. 生产源码不存在运行时 mock、业务 fixture 和 demo 控制器。
6. 菜单由真实 navigation 投影；403、空态、错误态和 requestId 可观察。
7. 受影响测试、静态检查和最终 CI 门禁通过；外部 Chrome 恢复后完成 1440×900 与 1280px 视觉对照。
