# V0.1 DEV 基础设施实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
> 任务标注【运维】= 需要在服务器/控制台由人执行并留证；【agent】= 产出文件/仓库内容。执行本计划的 agent 遇到【运维】步骤时输出清单等待人工回执，不得跳过。

**Goal:** 一台 16C/64G Linux 服务器上建成可重复重建的 DEV 单节点环境：GitOps 仓 + Flux 单向 Reconcile、①② 制品经 Gateway 单入口可访问、PG/etcd 备份到同机 MinIO（DEV-001 例外）并完成真实恢复演练。

**Architecture:** kubeadm 单节点（PCS 锁定版本）+ Cilium/Gateway API 作唯一北向入口；Flux 只从受保护 `engineering-platform-gitops` 仓 Reconcile；MinIO 为 `StorageBinding` gen-1；CloudNativePG 承载平台 PG 并经 Barman 推备份。

**Tech Stack:** Kubernetes 1.36.3（kubeadm）、containerd 2.3.1、Cilium 1.20.0、Gateway API CRD 1.6.1、Flux v2.9.3、cert-manager 1.21.1、local-path-provisioner、MinIO、CloudNativePG 1.30.0 / PostgreSQL 18.4 / Barman Cloud Plugin 0.13.0、kube-prometheus-stack 88.1.5、ghcr.io。

**Spec:** `docs/superpowers/specs/2026-08-09-dev-infra-v01-design.md`；治理例外 [DEV-001](../../architecture/deviations.md)

## Global Constraints

- 版本一律按 PCS 锁定值（附录 Runtime 组件清单），镜像/Chart 以精确版本或 digest 固定，禁 latest。
- GitOps 仓 main 受保护、禁止 direct push；一切集群变更经 PR；带外 `kubectl apply` 只用于 bootstrap 阶段且逐条记录进 runbook。
- 凭据不入 Git：MinIO/DB 凭据用 k8s Secret（bootstrap 手工创建 + runbook 登记名称与创建者，V0.2 起 OpenBao 接管）。
- 服务器操作全部留证：命令与输出摘录进 gitops 仓 `runbook/` 对应文档。
- ghcr.io 镜像：`ghcr.io/unif-code/engineering-platform-backend`、`ghcr.io/unif-code/engineering-platform`。

### Task 2:【运维】服务器核验与容器运行时

- [ ] **Step 1: 按 `runbook/00-server-baseline.md` 核验并回填实测值**（不达标先反馈决策，不继续）。

- [ ] **Step 2: 安装 containerd 2.3.1**

按发行版包管理安装 containerd 2.3.1（或官方二进制），生成默认配置并启用 cgroup v2 + systemd cgroup driver：

```bash
containerd config default | sudo tee /etc/containerd/config.toml
sudo sed -i 's/SystemdCgroup = false/SystemdCgroup = true/' /etc/containerd/config.toml
sudo systemctl enable --now containerd
containerd --version   # 期望 2.3.1
```

- [ ] **Step 3: 内核前置**

```bash
cat <<'EOF' | sudo tee /etc/modules-load.d/k8s.conf
overlay
br_netfilter
EOF
sudo modprobe overlay && sudo modprobe br_netfilter
cat <<'EOF' | sudo tee /etc/sysctl.d/k8s.conf
net.ipv4.ip_forward = 1
EOF
sudo sysctl --system
```

### Task 3:【运维】kubeadm 单节点集群

- [ ] **Step 1: 安装 kubeadm/kubelet/kubectl 1.36.3**（发行版对应的 k8s 社区仓库，版本钉死并 hold）。

- [ ] **Step 2: init**

先在 `/etc/hosts` 落稳定端点：`<服务器IP> dev-cp.unif.internal`（09：不把节点 IP 固化为 Cluster Identity）。

```bash
sudo kubeadm init \
  --kubernetes-version v1.36.3 \
  --control-plane-endpoint dev-cp.unif.internal:6443 \
  --pod-network-cidr 10.244.0.0/16 \
  --skip-phases=addon/kube-proxy
mkdir -p ~/.kube && sudo cp /etc/kubernetes/admin.conf ~/.kube/config && sudo chown $(id -u):$(id -g) ~/.kube/config
kubectl taint nodes --all node-role.kubernetes.io/control-plane-
```

（`--skip-phases=addon/kube-proxy`：Cilium 做 kube-proxy replacement。）

- [ ] **Step 3: Cilium 1.20.0 与 Gateway API CRD 1.6.1**

```bash
kubectl apply -f https://github.com/kubernetes-sigs/gateway-api/releases/download/v1.6.1/standard-install.yaml
helm repo add cilium https://helm.cilium.io && helm repo update
helm install cilium cilium/cilium --version 1.20.0 -n kube-system \
  --set kubeProxyReplacement=true \
  --set socketLB.hostNamespaceOnly=true \
  --set gatewayAPI.enabled=true \
  --set ipam.mode=cluster-pool \
  --set k8sServiceHost=dev-cp.unif.internal --set k8sServicePort=6443
kubectl -n kube-system rollout status ds/cilium --timeout=300s
kubectl get nodes   # 期望 Ready
```

- [ ] **Step 4: local-path-provisioner 并建逻辑 StorageClass**

安装 rancher local-path-provisioner（钉最新稳定版），再把逻辑名对齐架构文档：

```bash
kubectl apply -f https://raw.githubusercontent.com/rancher/local-path-provisioner/v0.0.31/deploy/local-path-storage.yaml
kubectl patch storageclass local-path -p '{"metadata":{"annotations":{"storageclass.kubernetes.io/is-default-class":"false"}}}'
```

随后由 Task 4 在 GitOps 仓提交名为 `stateful-rwo-lowlatency` 的 StorageClass（provisioner 同 local-path，`volumeBindingMode: WaitForFirstConsumer`、`reclaimPolicy: Retain`）——DEV 的 Provider Mapping 即本地盘（07/09 的逻辑类名保持不变）。

- [ ] **Step 5: 回执**：全部命令与 `kubectl get nodes -o wide` 输出进 `runbook/01-bootstrap.md`。

### Task 4:【运维+agent】Flux bootstrap 与基础设施清单

- [ ] **Step 1:【运维】Flux CLI v2.9.3 bootstrap**

```bash
flux --version   # 2.9.3

  --branch=main --path=clusters/dev --read-write-key=false

```

- [ ] **Step 2:【agent】提交基础设施 Kustomization（PR）**

`infrastructure/` 下按组件分目录，`clusters/dev/` 以 Flux Kustomization 串联（每个绑定显式 ServiceAccount；`--no-cross-namespace-refs=true` 由 bootstrap 生成的 kustomize-controller 部署 patch 补上）。组件：

1. `stateful-rwo-lowlatency` StorageClass（Task 3 Step 4 约定）。
2. cert-manager v1.21.1（HelmRelease，版本钉死；自签 ClusterIssuer `dev-selfsigned`）。
3. MinIO：单副本 Deployment + PVC（`stateful-rwo-lowlatency`，数据盘路径，500Gi 内合理配额）+ cert-manager 签发的 TLS + Service。镜像钉具体 RELEASE tag。
4. MinIO 初始化 Job（`mc` 镜像）：建 bucket `postgres-backup`、`etcd-backup`、`audit-worm`（后两者 `--with-lock`），三个独立用户与最小策略；凭据从手工 Secret 读取。
5. kube-prometheus-stack 88.1.5 HelmRelease：单副本、Grafana Managed Alerting off、告警规则四条（NodePressure、FluxReconcileFailed、CNPGBackupFailed、MinIODown）。

- [ ] **Step 3:【运维】创建 bootstrap Secrets 并登记**

```bash
kubectl create ns minio; kubectl create ns cnpg-system; kubectl create ns platform
kubectl -n minio create secret generic minio-root --from-literal=user=admin --from-literal=password="$(openssl rand -base64 24)"
# 输出的密码存入团队密码库；runbook/02-secrets.md 登记 Secret 名称/命名空间/保管人（不记录值）
```

- [ ] **Step 4: 合并 PR，验证 Reconcile 与例外验证**

`flux get kustomizations` 全 Ready；MinIO 控制台可达；验证 Object Lock：向 `audit-worm` 放一个带保留期的对象并尝试删除应被拒（命令与输出进 `runbook/03-minio-verify.md`，首页醒目标注 DEV-001 与关闭期限）。
